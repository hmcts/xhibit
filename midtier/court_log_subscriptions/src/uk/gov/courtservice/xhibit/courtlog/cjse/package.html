This package and it's children provide the functionality to convert an incoming XHIBIT court log event into an outgoing CJSE court log event.

Event Processing

The processing of an event has been broken down into the following steps:

  • Receive the incoming court log event as a JMS message and extract the value object representing the event.
  • Analyse the value object and retrieve objects to do the following processing:
    • Map the XHIBIT event to a CJSE event identifier and message.
    • Construct the human readable message that goes with the event.
    • Construct the machine readable event parameter XML.
  • Write the event to the database so that Mercator can pass the event on.

Event Classification

Events are classified in two main ways, by how the static ordinality of how they map from court log events to cjse events and by their event level. At present a single input event generates a single output event so the dynamic ordinality is always one to one. Static ordinality refers to how an incoming court log event maps to the outgoing cjse event.The major static ordinality types look like:

  • One to one means that a court log event of type CL-A can only ever map to a CJSE event of type CJSE-A.
  • One to many means that a court log event of type CL-B depending on the data it is carry in can map to one of the CJSE events CJSE-B, CJSE-C or CJSE-D.
  • Many to one means that court log events of type CL-C, CL-D or CL-E will all map to CJSE event CL-E.
The event level represents against which 'entity' the event occurs, the major event levels are: Case, Defendant and Charge.

Package Structure

The package structure is laid out to group the elements of the component in a rational way.

  • uk.gov.courtservice.xhibit.courtlog.cjse:
    Contains the components that handle behaviour common to all events.
    • uk.gov.courtservice.xhibit.courtlog.cjse.eventlevel:
      Contains components that perform processing specific to a certain event level, most especially the ones that construct the xml event parameters.
    • uk.gov.courtservice.xhibit.courtlog.cjse.eventmapper:
      Contains components that handle the mapping from a court log event to a cjse event.
    • uk.gov.courtservice.xhibit.courtlog.cjse.eventmessage:
      Contains components for constructing the human readable message.

Event Configuration

The components contained in this package have been designed to be highly configurable so that as much as possible, the addition of a new event will involve only an alteration to configuration files. This is facilitated as much as possible the use of the factory pattern to provide a consistent interface to the other portions of the application.

The major configuration file is the 

/config/xml/cjse_integration/mapping.xml

file, which provides details of the overall mapping of events. This mapping file is parsed by more than one class, at the top level the CjseSwitchHandler provides the parsing of common elements, while specific implementations of CjseEventMapper parse more specific elements. For example:
<!-- Handled by CjseSwitchHandler -->
<CJSE_CL_CONFIGURATION>
    <!-- Handled by CjseSwitchHandler -->
    <INCOMING_EVENT xhibitid="11111"
                    level="CASE"
                    type="ONETOMANY">
        <!-- Handled by OneToManyCjseEventMapper -->
        <DIFFERENTIATING_FIELD xpath="XXX/YYY/ZZZ/text()"/>
        <!-- Handled by OneToManyCjseEventMapper -->
        <EVENT fieldvalue="ABC" cjseid="11112" cjsemessagecode="testGetMessageForMessageCode"/>
        <!-- Handled by OneToManyCjseEventMapper -->
        <EVENT fieldvalue="DEF" cjseid="11113" cjsemessagecode="testGetMessageForMessageCode"/>
    <!-- Handled by CjseSwitchHandler -->
    </INCOMING_EVENT>
    ...
<!-- Handled by CjseSwitchHandler -->
</CJSE_CL_CONFIGURATION>
The attributes of incoming event are common to all events:
  • xhibitid the identifier value for the incoming event.
  • level the level of the incoming event. Determines which event level this event has, the value of this field is passed to the CjseEventLevelPopulatorFactory to retrieve the CjseEventLevelPopulator appropriate for this event.
  • type the mapping of the incoming event. Determines how the mapping is handled, the CjseEventMapperHandler that is used to configure the event mapper is retrieved from the CjseEventMapperHandlerFactory using this value.
For details of the individual event mapper configuration please refer to their documentation.
