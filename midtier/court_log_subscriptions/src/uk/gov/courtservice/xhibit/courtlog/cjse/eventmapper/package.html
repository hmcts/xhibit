This package contains the classes concerned with the determination of which CJSE event should be generated for a given incoming court log event.

Package Usage

The main entry points to this package are via the CjseEventMapperHandlerFactory class and the CjseEventMapperHandler and CjseEventMapper interfaces.

  • CjseEventMapperHandlerFactory provides instances of CjseEventMapperHandler based on the type requested, the type request is intended to originate with CjseSwitchHandler.
  • CjseEventMapperHandler then parses elements of the mapping.xml that is being parsed by CjseSwitchHandler in order to configure an instance of CjseEventMapper. Different implementations of this interface can determine what XML they expect, thus the basic mapping.xml can be extended almost indefinitely.
  • The CjseEventMapper thus configured is recorded in an instance of CjseEventPopulator in the CjseEventPopulator map generated by CjseEventPopulatorMapFactory. When a court log event comes in the CjseEventMapper is responsible for determining which CJSE event ID and event message is relevant for that particular court log event.

Configuration

Configuration of the CjseEventMapperHandlerFactory is handled via the properties file

/config/components/cjse.event.mapping.properties
that is retrieved via CSServices.getConfigServices().getProperties(String Properties) this properties file provides a list of mapping type and the CjseEventMapperHandlers that handle them. For example:
define.mapping.ONETOMANY=uk.gov.courtservice.xhibit.courtlog.cjse.eventmapper.OneToManyCjseEventMapperHandler
define.mapping.ONETOONE=uk.gov.courtservice.xhibit.courtlog.cjse.eventmapper.OneToOneCjseEventMapperHandler

Configuration of the individual CjseEventMapper instances are handled by the relevant CjseEventMapperHandler.
