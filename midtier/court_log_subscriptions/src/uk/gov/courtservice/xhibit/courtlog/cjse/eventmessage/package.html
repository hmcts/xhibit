Provides classes which generate the dynamic elements of the CJSE Message component of the CJSE event.

Package Specification

Each event which is sent to the CJSE contains a message component which is a textual descroption of the event. Each distinct message required for the CJSE is given a message code and stored in the CjseEventMessageText bundle under /config/bundles for each language in use in the system.

The message structure comprises of static text and tokens describing message elements, for example message 1257 appears as:

1257=$$$CourtIdentification$$$ $$$CaseNumber$$$ $$$EventDateTime$$$ Reserved to $$$ReservedToJudge$$$

The tokens in between the '$$$' separators indictate that this portion of the message is to be provided by the given mesage element, for example 1257 uses message elements:

  • CourtIdentificationMessageElement
  • CaseNumberMessageElement
  • EventDateTimeMessageElement
  • ReservedToJudgeMessageElement
  • StringMessageElement

The configuration file /config/components/cjse.event.message.elements.properties defines the class which is used to provide each message element, for example this file contains an entry:

CourtIdentification=uk.gov.courtservice.xhibit.courtlog.cjse.eventmessage.CourtIdentificationMessageElement

indication that the token CourtIdentification in the message structure will be provided by the class uk.gov.courtservice.xhibit.courtlog.cjse.eventmessage.CourtIdentificationMessageElement

See below for further information on the StringMessageElement.

Application flow to build a CJSE message component:

The entry point to the message functionality is the MessageFactory.

The MessageFactory contains a 'lazy instantiated' Map of MessageBuilders keyed on MessageBuilderKey, where the MessageBuilderKey consists of the message code (1257 in the example) and the locale.

On the first request for a given MessageBuilder the MessageFactory will uses the MessageElementFactory to retrieve the MessageElements required for a given message text. An instance of the MessageBuilder class is then created with these MessageElements and stored in the Map for future requests.

The MessageBuilder class can then be used to generate the message text for this message component, this is achieved by looping through the MessageElement array and calling each MessageElement class to provide it's section of the message text.

Each MessageElement contains the logic to build a dynamic section to the message test. The StringMessageElement is a special case of MessageElement. This may take the form of retrieving data from the database, or retrieving data from the xhibit court log xml. Details of paths to information in the cort log xml are retrieved by the MessageElement from the config file /config/components/cjse.event.properties. If no special processing is required for a section of the message text i.e. a staic section such as ' Reserved to ' in the example above, a StringMessageElement is constructed which simply returns this string.

Summary of configuration files used

  • /config/bundles/CjseEventMessageText_en_GB - Contains English versions of all CJSE event messages with tokens to indicate where MessageElements are used
  • /config/components/cjse.event.message.elements.properties - defines the class which is used to provide each message element
  • /config/components/cjse.event.properties - contains xpath references to retrieve information from xhibit court log events
